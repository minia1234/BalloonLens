## 3. 제품 방향: '원문 위에 무해하게 번역'이 우선

서비스의 핵심 사용자 경험은 (1) 페이지를 열고 번역 켜기, (2) **첫 화면의 대사가 빠르게 표시**, (3) 의심스러운 대사만 짧게 수정, (4) 다음 페이지에서 이름/말투 유지, (5) 원문 원클릭 복구다. 자동 레이아웃과 고급 AI 성능이 좋아도 텍스트가 그림을 가리거나 작업이 멈추면 실사용 실패다.

**실사용 모드 3가지(권장):**
1. **빠른 보기(기본)** — 비파괴 오버레이, 불확실한 영역은 표시/편집, 캐시 우선. 작은 글자를 억지로 지우지 않는다.
2. **말풍선 식자** — 검증된 닫힌 풍선에서 텍스트 마스크 기반 정리·맞춤을 시도. 충돌 시 빠른 보기로 후퇴.
3. **정밀 보기(선택)** — 사용자가 지정한 페이지/영역에만 높은 비용의 분할+인페인팅/재OCR 적용. 처음부터 모든 이미지에 무거운 GPU 추론을 추가하지 않는다.

기능 확장을 서두르기 전에 '독서에 방해되지 않는 번역'의 성공률을 높여야 한다.

## 4. 알고리즘 개선: 단계별 후보, 채택 조건

### 4.1 탐지 · 풍선 분할

- **기준선:** EasyOCR CRAFT가 검출한 텍스트 박스를 휴리스틱으로 병합하고, `presentation.py`가 밝은 폐영역을 찾는다.
- **후보 A — comic-text-detector (CTD/DBNet)**: 텍스트 블록과 마스크의 정확도 비교용. 파생 모델/코드의 GPL 등 라이선스를 별도 확인.
- **후보 B — RT-DETR/말풍선+텍스트 검출기**: 텍스트+말풍선의 소속 관계를 학습 기반으로 찾는 대안. 모델 재배포 및 상용 사용 조건 확인.
- **후보 C — Koharu RF-DETR 계열**: 최종 품질 비교용(자원 비용이 클 수 있음).
- **원칙:** CRAFT를 즉시 제거하지 않는다. 디텍터를 `DetectionProvider` 인터페이스로 추상화한 뒤 같은 코퍼스에서 recall, 빈 풍선 오탐, 처리시간, VRAM을 비교한다.

### 4.2 OCR

- 일본어 Manga OCR는 그대로 기준선으로 유지한다. 인식 실패 ROI에 한해서 확대, 대비, 2차 OCR을 적용한다.
- PP-OCRv6 Manga 계열 등 특화 모델을 **실제 라이선스·가중치 출처 확인 후** 테스트한다.
- 수직 대사/오른쪽→왼쪽 열 순서를 검출 박스만으로 결정하지 말고 '열 후보 → 풍선 소속 → 컷 순서' 계층으로 묶는다.
- 타일 경계 주변은 IoU만 아니라 OCR 문자열 및 위치 정합으로 중복/누락을 판정한다.

### 4.3 배경 복원 · 식자

- 1순위: 검증된 단색/밝은 폐풍선에서 국소 마스크 기반 페인트.
- 2순위: 텍스트 모양 마스크 + 고전적 inpainting(Telea 등) 성능/아트 보존 비교.
- 3순위: 인물/배경 위 글자에서만 LaMa/AOT 계열 검토. 별도 모델 다운로드·VRAM 설정이 필요하다.
- `fitGrowing`는 **가독성 보장 기능이면서 아트 침범 위험**이 있다. 다른 대사 상자와 겹치면 확대 중지, `overflow` 표기와 클릭 전문 보기 유지.
- 레이어는 원본 / 마스크 / 지움 / 번역문으로 분리하여 즉각 토글 가능하게 한다.

### 4.4 번역 및 문맥

- 캐시 키에 모델/언어/프롬프트/작품·용어 변경을 유지하고, 캐시 품질 마킹을 보강한다.
- 청크 병렬 시 앞 청크의 번역을 볼 수 없으므로 **고정된 인물 목록·문체 규칙·호칭 맵**을 모든 청크에 동일하게 전달한다. 근거 없는 자동 추론을 확정 저장하지 않는다.
- 선택 가능한 번역 속도 모드: **빠름(병렬 3)** / **일관성(청크 순차 1)**. 모델 호출 횟수와 한도 예상치를 UI에 함께 알린다.
- 오류 재시도는 텍스트 내용 변경/형식 위반만 제한적으로, 타임아웃 후 무조건 재호출은 금지한다. 쿼터는 **공식 공급자 사용량이 아닌 로컬 기록 기반**으로 명시한다.
- Claude/Codex 구독 CLI 사용 가능 범위·자동화 정책은 공식 약관에 따라 별도 검토한다. Codex는 현재 샌드박스 점검 실패 환경에서 사용 불가 상태를 유지한다.

## 6. 품질 평가 설계(실제 사용 데이터가 생기면 수치 확정)

### 샘플링 및 저작권
- 사용자 권리/열람 권한이 있는 평가 이미지 위주로, 원본 공개나 무단 업로드를 하지 않는다.
- 우선 **30페이지 이상**, 일본어 세로/가로·영어·장문 웹툰·흑백/컬러·어두운 풍선·효과음·외부 텍스트를 분리한다.
- 정답 데이터: 이미지 ID, 텍스트 박스 polygon, 읽기 순서, OCR 원문, 한국어 참조문, 인명/어투, 기대 마스크(선택).
- 합성 데이터는 유닛 테스트로만 사용하고 **실화면 품질 수치에 합산하지 않는다**.

### 측정 지표
| 단계 | 지표 | 판단 |
|---|---|---|
| 탐지 | 텍스트 영역 recall/precision, 말풍선 단위 누락 | 누락률 큰 페이지의 사례별 개선 |
| OCR | 문자 오류율(CER), 줄 병합/열 순서 오류 | 일본어 세로/특수 폰트 따로 비교 |
| 번역 | 의미/인칭/화행 보존, 인명·존댓말 일관성, 확인 필요 비율 | 두 평가자가 블라인드 비교 |
| 레이아웃 | 잘림/충돌/아트 가림/원문 복원 실패 | 브라우저 배율·리사이즈 포함 |
| 성능 | 첫 대사 표시 p50/p95, 전체 완료, GPU VRAM, 캐시 적중 | 콜드/웜/모델별 분리 |
| 사용성 | 첫 실행 성공률, 수동 수정 소요, 실패 후 재시도 성공률 | 5명 정도의 소규모 태스크 관찰로 시작 |

## 7. 코드 분할·버전 관리 제안

```text
helper/balloonlens/
  detection/       # NEW: Detector protocol + CRAFT adapter / optional ML adapter
  ocr.py           # 기존 OCR 전략 유지, 재인식 로직을 detector와 분리
  presentation.py  # 풍선/텍스트 마스크 결과와 오버레이 출력 계층 분리
  backends/        # 현재 구조 유지; job-scoped process cancellation 보강
  jobs.py          # 우선순위/세션 취소/관측 공통화
extension/
  reading.js       # 순수 함수: 배치·충돌 탐색·측정 결과
  content.js       # DOM 어댑터만 남기기 (독서 스크립트 대형화 제어)
  sw.js            # 권한 있는 네트워크·캡처만 담당
tests/             # 품질 코퍼스 인덱스/라이선스/기대 결과(원본은 저장소 외부)
```

- 변경 단위는 각각 PR로 쪼갠다. 현재 동작하는 로컬/구독 경로를 한 번에 교체하지 않는다.
- 품질 기능은 feature flag 뒤에서 A/B 비교하고, 원본 오버레이 모드를 항상 유지한다.
- 위 계획의 완료 체크는 **작성된 코드** 기준이다. 실제 장치 실행·크롬 설치·번역 결과 확인은 별도로 필요하다.

# 사용자 편의성 검토 (2026-10-10)

이 문서는 BalloonLens를 실제로 쓰는 사람의 흐름을 따라가며 마찰을 찾고, 다른 소프트웨어의 방식을 참고해 개선 순서를 정한 것이다.

## 1. 누가 쓰나

- 만화를 읽는 일반 사용자다. 개발 도구에 익숙하지 않고, 설치는 한 번, 번역은 매일 한다.
- 가장 중요한 것은 두 가지다. 설치가 끝났는지 알 수 있어야 하고, 막히면 다음 행동을 바로 알 수 있어야 한다.

## 2. 흐름별 마찰과 조치

| 단계 | 사용자가 하는 일 | 마찰 | 심각도 | 조치 |
|---|---|---|---|---|
| 1. 받기 | ZIP을 받아 푼다 | 파일이 많아서 어디를 눌러야 할지 모른다 | 중 | exe를 ZIP 최상위에 두고 README 첫 줄에 안내 (완료) |
| 2. 설치 시작 | 설치 창을 연다 | 설치 중 무엇을 하는지 안 보인다 | 높음 | 단계 번호와 진행 막대, 경과 시간을 표시 (완료, D49) |
| 3. 번역 패키지 | 기다린다 | 수 GB, 여러 분 걸린다 | 높음 | 시작 전과 단계 안에서 시간을 미리 알린다 (완료) |
| 4. 로그인 | Claude/Codex에 로그인한다 | 명령을 직접 입력해야 한다 | 중 | 로그인 창 버튼이 명령을 채운 창을 연다. 로그인은 사람이 한다 (완료) |
| 5. 크롬 확장 | 크롬에서 확장을 로드한다 | 3단계가 수동이고, 끝났는지 알 수 없다 | 가장 높음 | 3단계 안내 창과 자동 완료 감지 (완료, D44–D46). 자동 설치는 크롬 제약으로 불가 |
| 6. 첫 번역 | 팝업을 본다 | "처음 설정이 필요해요"만 나오고 무엇을 할지 모른다 | 중 | 행동 안내 문구로 바꿈 (완료, D50) |
| 7. 도우미 오류 | 팝업 오류를 본다 | "기록 파일을 확인해 주세요"는 일반 사용자에게 의미가 없다 | 높음 | 설치 창을 열고 "상태 다시 확인" 하라고 안내 (완료) |
| 8. 포트 충돌 | 번역이 안 된다 | 다른 프로그램이 8787을 쓰는 것을 알 수 없다 | 높음 | 헬퍼가 자기 자신인지 확인하고, 다른 프로그램이면 이름을 알린다 (완료, D42) |
| 9. 문제 보고 | 개발자에게 상황을 알린다 | 로그 파일 위치를 모른다 | 중 | 로그 파일 열기, 데이터 폴더 열기 버튼 (완료) |
| 10. 업데이트 | 새 버전을 받는다 | 자동으로 알려 주지 않는다. ZIP을 다시 받아 풀어야 한다 | 높음 | 제안 (아래 로드맵 3) |
| 11. 제거 | 등록을 지운다 | 데이터를 지울지 알기 어렵다 | 낮음 | 등록 해제 버튼은 데이터를 남긴다고 안내한다 (있음) |

## 3. 다른 소프트웨어에서 배운 것

- **번역 확장 (Immersive Translate).** 크롬 웹 스토어의 "Add to Chrome" 한 번으로 설치하고, 첫 실행에는 대상 언어와 번역 서비스 두 가지만 고르게 한다. 개발자 문서는 스토어에 접근이 막힐 때 ZIP이나 CRX로 수동 설치하는 방법을 따로 안내한다 ([manual](https://immersivetranslate.com/en/manual-chrome-extension/), [대학 안내](https://www.hkmu.edu.hk/oetools/?p=23854)). 우리는 지금 수동 설치만 있어서 가장 큰 차이가 난다.
- **로컬 AI 도구 (Ollama).** 설치 프로그램 하나로 끝나고, 설치 후에는 백그라운드 서비스로 돌면서 트레이 아이콘이 상태를 보여 준다. 로그는 정해진 폴더에 모은다 ([문서](https://docs.ollama.com/windows)). 우리 설치 창이 상태를 보여 주는 역할을 하고, 로그 버튼을 추가해 같은 방향으로 맞췄다. 트레이 아이콘은 다음 단계 후보다.
- **크롬 웹 스토어 배포.** 개발자 등록비는 한 번 5달러라고 보도됐다 ([2020 보도](https://9to5google.com/2020/03/12/chrome-web-store-fee/)). 현재 가격은 대시보드에서 다시 확인해야 한다. 공개하지 않는 "비공개(unlisted)" 게시는 링크를 가진 사람만 설치할 수 있다고 Google 문서가 설명한다 ([문서](https://developer.chrome.com/docs/webstore/cws-dashboard-distribution)). 스토어로 올리면 확장 ID가 바뀐다.
- **강제 설치 정책.** HKCU와 HKLM 중 어느 쪽이 우선하는지 자료마다 다르다 ([PixieBrix](https://docs.pixiebrix.com/enterprise-it-setup/browser-extension-installation-and-configuration/browser-extension-installation-policy/windows-registry), [Trend Micro](https://success.trendmicro.com/en-US/solution/KA-0021157)). 실제 크롬에서 확인하기 전에는 채택하지 않는다 (D47).

## 4. 개선 로드맵

1. **완료.** 설치 진행 표시, 행동 안내 문구, 로그·데이터 폴더 버튼, 포트 충돌 안내, 크롬 확장 안내 창과 자동 완료 감지.
2. **사용자 결정 필요 (추천: 진행).** 크롬 웹 스토어 비공개 게시.
   - 장점: "Add to Chrome" 한 번으로 설치되고, 업데이트가 스토어를 통해 자동으로 온다. 가장 큰 마찰이 사라진다.
   - 필요한 것: 개발자 등록비 (현재 가격 확인), 심사, 확장 ID 변경.
   - ID가 바뀌면 헬퍼 허용 목록(`BALLOONLENS_EXTENSION_IDS`), 설치 스크립트의 네이티브 호스트 `allowed_origins`, 테스트와 문서를 함께 바꿔야 한다. 전환 기간에는 두 ID를 모두 허용하면 된다.
   - 위험: 구독 CLI 자동화의 약관 검토가 아직 남아 있다 (계획서 M0 #9). 개인정보 처리 내용을 스토어 설명에 정확히 적어야 한다. 초안은 `2026-10-10-store-listing-draft.md`에 있다.
3. **제안.** 업데이트 확인. 설치 창이 현재 버전과 새 버전을 비교해 알려 준다. 스토어 배포 후에는 크롬이 확장 업데이트를 맡으므로, 이 항목은 스토어 결정 뒤에 다시 본다.
4. **제안.** 첫 실행 안내를 한 곳으로 모은다. 확장의 "시작하기" 화면과 설치 창이 같은 단계를 두 번 말하지 않게 역할을 나눈다.
5. **보류.** 강제 설치 정책. 크롬에서 직접 검증한 뒤에만 채택한다. 사용자 브라우저가 "관리되는 브라우저"로 바뀌므로 사용자가 결정한다.
6. **제안.** 트레이 아이콘으로 도우미 상태 표시. 효과는 있지만 비용이 크다. 스토어 배포 후 필요성을 본다.

## 5. 아직 못 한 것

- 빈 Windows 프로필에서 ZIP부터 설치하는 시험.
- 실제 크롬에서 "크롬 확장 페이지 열기"가 `chrome://extensions`를 여는지 확인 (이 환경의 임시 프로필에서는 열리지 않았다).
- 실제 사용자 관찰. 이 검토는 개발자가 흐름을 따라간 것이며, 실제 사람이 쓰는 모습을 본 것은 아니다.

# 번역 준비와 표시 준비의 대기 줄이기

목표: 현재 Claude 모델, 입력 문맥, 검수, 호출 한도를 유지하면서 서로 독립적인 준비 작업을 겹친다.

시작 상태: 미커밋 OCR 파이프라인·warm pool 변경이 이미 존재한다. 그 상태에서 Python 247개, Node 41개 통과.
기존 파일은 `bench_out/latency-overlap-before/`에 필요한 소스만 보관했다. 기존 변경과 이번 추가 변경을 구분하는 비교용이다.

1. `backends/page.py`, `backends/claude_cli.py`, `jobs.py`: 사용량·로그인 확인과 작품 지침 조회가 끝나면 해당 번역 프롬프트의 프로세스를 준비한다. 실제 번역 요청은 OCR 뒤에만 전송한다. 검사: 첫 OCR 전에 준비됨, 준비만으로 모델 호출이나 사용량 기록이 생기지 않음, 차단된 작업은 준비하지 않음.
2. `backends/warm.py`, `claude_cli.py`: 번역 요청은 준비 완료된 프로세스를 우선 사용하되, 모두 시작 중이면 이미 시작된 하나를 사용한다. 검사: 새 프로세스로 같은 시작 지연을 반복하지 않음, 다른 프롬프트·모델의 프로세스를 사용하지 않음, 취소·만료·종료 회귀 통과.
3. `jobs.py`: 전체 OCR 뒤 말풍선 표시를 준비하면서 번역 완료를 기다린다. 표시 준비에는 번역 결과가 필요하지 않다. 검사: 표시 준비와 번역의 동시 진행, 최종 문장·배치 유지, 취소 회귀 통과.

검증 순서: 실패 재현 테스트 → 최소 구현 → 관련 테스트 → 전체 Python/Node 회귀 → 동일한 입력·고정 지연으로 변경 전후 비교. 실제 Claude 응답 속도나 실제 만화 품질로 모의 측정값을 해석하지 않는다.

대안: 모델 변경은 품질 비교가 필요하고, 호출 수·동시 실행 수 증가는 한도 소모에 영향을 준다. 이번에는 독립적인 준비 작업의 대기만 줄인다.

Claude CLI 입력·출력 옵션 참고: https://code.claude.com/docs/en/cli-reference

## 적용 및 검증 결과

- 이미지 OCR 전에 현재 원문·목표 언어·작품 지침에 맞는 프로세스를 준비한다. 준비 자체는 모델 요청이나 사용량 기록을 만들지 않는다. 로그인·한도로 막힌 작업은 준비하지 않는다.
- 준비된 프로세스를 우선 사용하고, 없으면 같은 키로 이미 시작 중인 프로세스를 사용한다. 이 경우 `warm_calls`에는 예열 완료로 집계하지 않는다. CLI 시간에는 프로세스 생성도 포함한다.
- OCR 결과를 얻으면 번역과 독립적으로 말풍선 표시를 준비하고, 남은 번역 시간만 기다린다.
- 신규 회귀 테스트에서 준비 순서, 시작 중 프로세스 재사용, 표시 준비의 동시 진행이 기존 코드에서 실패함을 확인한 뒤 수정했다.
- 관련 테스트 36개 통과. 전체 Python 테스트 255개 통과(기존 Starlette/AnyIO 폐기 예정 경고 1개), Node 테스트 41개 통과. 실행 중 별도 OCR 프로파일 테스트가 작업 폴더에 추가되어 시작 시점과 전체 테스트 수가 다르다.
- 실제 로컬 도우미 + 실제 OCR + 가짜 Claude CLI 연결 검증: `tools/e2e_subscription.py --with-ocr` 16/16 통과. 설치된 모델만 사용하도록 Hugging Face를 오프라인으로 실행했다.
- 설치된 Claude Code 2.1.285의 로그인 상태 `ready`. 새 준비 경로에서 실제 CLI 초기화 응답을 859ms에 확인했다. 모델 요청은 보내지 않았다.

### 고정 지연 비교

`bench_out/latency_overlap_bench.py`로 변경 직전 작업 폴더와 수정 후를 각 5회 측정했다. 매회 새 프로세스 풀과 빈 캐시를 사용했다. 가짜 CLI의 초기화 지연은 200ms, OCR 지연은 350ms, 표시 준비 지연은 250ms이다. 모델 요청은 없다.

| 중앙값 | 변경 전 | 변경 후 | 감소 |
|---|---:|---:|---:|
| 전체 처리 | 931ms | 631ms | 32.2% |
| 첫 번역문 | 669ms | 433ms | 35.3% |

10회 모두 최종 말풍선 데이터가 동일하고 페이지당 번역 단계는 1회였다. 원본 측정 파일은 `bench_out/latency-before.json`, `bench_out/latency-after.json`에 있다. 이는 독립적인 준비 작업을 겹친 효과를 확인하는 모의 실험이며 실제 Claude 응답·실제 만화 품질·사이트 체감 속도의 증거는 아니다.

## 실행 중 도우미 반영

8787 포트의 도우미가 이 프로젝트의 `helper/.venv/Scripts/pythonw.exe`에서 시작되었고 작업 수가 0임을 확인했다. 종료·재시작 명령은 자동 승인 심사에서 `blocked by policy`로 거부되어 실행되지 않았다. 소스 변경은 저장되어 있으며 실행 중인 도우미에 적용하려면 사용자가 도우미를 한 번 재시작해야 한다.
